## What this is, and why it matters for Aegis, in one paragraph

MCP revision `2026-07-28` is the one that **made MCP stateless**: it removes the
`initialize`/`notifications/initialized` handshake, removes protocol-level sessions and the
`Mcp-Session-Id` header, and moves the protocol version and client capabilities into
per-request `_meta` keys **[DOC]**
(https://modelcontextprotocol.io/specification/2026-07-28/changelog, major changes 1 and 2).
It matters for Aegis more than for most servers, because the property Aegis's MCP front door
went out of its way to hand-build — *scope is per call, not per connection*, re-verifying the
token and re-reading the caller's authority from the `users` table on every single message
**[SOURCE]** (`backend/src/app/mcp/server.py:22-42`) — is now **the protocol's own model**.
Aegis was early to the right answer. This revision makes that answer standard, and it also
adds cache hints on list results, a discovery RPC, a redesigned server-asks-client pattern,
and documented OpenTelemetry trace-context propagation that plugs straight into the existing
span tree.

## The finding that changes this plan: **the builder does not need swapping**

The brief says `backend/src/app/mcp/server.py` "uses the OLD `StreamableHTTPSessionManager`
path around line 1395-1462". It does — `build_http_app` at
`backend/src/app/mcp/server.py:1395` ends in `return server.streamable_http_app(...)` at
`:1438` **[SOURCE]**. But in `mcp 2.0.0` **that same builder already serves the new era**.

`StreamableHTTPSessionManager._handle_request` routes by the `MCP-Protocol-Version` header:
anything not in `HANDSHAKE_PROTOCOL_VERSIONS` — including `2026-07-28` — goes to
`handle_modern_request`, and only the four handshake versions reach the legacy stateful or
stateless paths **[SOURCE]**
(`backend/.venv/…/mcp/server/streamable_http_manager.py:172-192`).

I built a server the same way `build_http_app` does and drove it over an in-process ASGI
transport **[MEASURED]**:

```
--- server/discover -> HTTP 200
{"jsonrpc":"2.0","id":1,"result":{"cacheScope":"private","capabilities":{"tools":{"listChanged":false}},
 "resultType":"complete","supportedVersions":["2026-07-28"],"ttlMs":0,
 "_meta":{"io.modelcontextprotocol/serverInfo":{"name":"probe","version":"0.0.1"}}}}

--- tools/list -> HTTP 200
{"jsonrpc":"2.0","id":2,"result":{"cacheScope":"private","resultType":"complete",
 "tools":[{"description":"d","inputSchema":{"type":"object"},"name":"echo"}],"ttlMs":60000,
 "_meta":{"io.modelcontextprotocol/serverInfo":{…}}}}

--- tools/call -> HTTP 200
{"jsonrpc":"2.0","id":3,"result":{"content":[{"text":"{\"meta\": {
   \"io.modelcontextprotocol/protocolVersion\": \"2026-07-28\",
   \"io.modelcontextprotocol/clientCapabilities\": {},
   \"traceparent\": \"00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01\"},
   \"pv\": \"2026-07-28\"}","type":"text"}],"isError":false,"resultType":"complete",…}}
```

That single run establishes five things at once **[MEASURED]**:

1. **`server/discover` answers with no work from us** — `Server._handle_discover` is a
   default handler that auto-derives capabilities from registered handlers **[SOURCE]**
   (`mcp/server/lowlevel/server.py:657-676`).
2. **`resultType: "complete"` is stamped by the SDK** on every result.
3. **`ttlMs` / `cacheScope` are emitted**; `ttlMs: 60000` came from the
   `cache_hints={"tools/list": CacheHint(ttl_ms=60000, scope="private")}` I passed, and
   `server/discover` — which I gave no hint — defaulted to `ttlMs: 0, cacheScope: "private"`.
4. **`traceparent` in `params._meta` arrives intact in `ctx.meta`.**
5. **`_meta["io.modelcontextprotocol/serverInfo"]` is stamped automatically.**

I also confirmed the strictness of the new envelope **[MEASURED]**: omitting
`io.modelcontextprotocol/clientCapabilities` gets
`{"code":-32602,"message":"params._meta is missing the required envelope key(s): io.modelcontextprotocol/clientCapabilities"}`
with HTTP 400, and an `initialize` request under the 2026 header is rejected the same way —
the handshake is genuinely gone, not merely discouraged.

And against **the repo's own app**, unauthenticated **[MEASURED]**:

```
no-auth modern -> 401  Bearer error="invalid_token", error_description="Authentication required",
                       resource_metadata=".../.well-known/oauth-protected-resource"
```

So the SDK's `AuthenticationMiddleware` / `RequireAuthMiddleware` chain sits **ahead** of era
routing. Aegis's "an unauthenticated request never reaches a handler" property **[SOURCE]**
(`server.py:15-20`) survives the new era unchanged. **I could not measure an authenticated
modern round-trip against the repo app** — that path needs a live Postgres and a seeded
principal, which I did not stand up. **That is the single biggest untested claim in this
document** and it is task M1.

**Conclusion:** this is not a migration. It is a **configuration and verification** exercise
on a stack that already speaks the revision. Do not budget it as a rewrite, and do not let
anyone write "swap the builder" in a commit message — there is nothing to swap.

## Data / schema changes

**None.** Nothing in this revision touches Aegis's tables. The one place a schema question
could arise — major change 1's "servers that need cross-call state use explicit,
server-minted handles passed as ordinary tool arguments" **[DOC]** — does not apply, because
Aegis's MCP server is deliberately stateless already: it re-resolves the caller from

**[SOURCE]** (`server.py:29-36`). There is no per-session state to migrate to handles.

**Checkable:** four assertions, one per bullet, in a new
`backend/tests/mcp/test_modern_protocol.py`.

### M2 — `ttlMs` / `cacheScope` on `tools/list`, chosen deliberately

The SDK fills these from `cache_hints` on the constructor, per field, and **a value the
handler set explicitly always wins** **[SOURCE]** (`mcp/server/caching.py:44-58`,
`apply_cache_hint`). Without a hint the default is `ttlMs: 0, cacheScope: "private"`
**[MEASURED]**.

**`cacheScope` MUST be `"private"` for Aegis, and this is a security decision, not a tuning
knob.** `tools/list` is persona-filtered per caller **[SOURCE]** (`server.py:56-60`,
`app/adapter/tools.py:791`). `"public"` tells shared intermediaries they may serve one
caller's tool list to another **[DOC]** (minor 5). `"private"` is already the default, which
means **the failure mode here is someone "optimising" it later**, not someone forgetting it.

`ttlMs` is a genuine choice. The list changes when a persona's allowlist or an external
peer's grant changes — grants are written by `PUT /v1/mcp/tools/{tool_name}/grant`
**[SOURCE]** (`backend/src/app/api/routes_mcp.py:31-33`). A short TTL (30–60 s) is honest; a
long one means a revoked grant keeps being listed. **Pick a number and defend it in a
comment.**

**Checkable:** a modern `tools/list` returns the chosen `ttlMs`; a test asserts
`cacheScope == "private"` and names the reason.

### M3 — `traceparent` through `_meta` into the existing spans — **verify, do not build**

`OpenTelemetryMiddleware` is **on by default**: `self.middleware = [OpenTelemetryMiddleware()]`
in `Server.__init__` **[SOURCE]** (`mcp/server/lowlevel/server.py:433-439`, with the comment
"ships on by default so every server emits a…"). It opens a `SpanKind.SERVER` span per
inbound message named `f"{ctx.method} {target}"`, sets `mcp.method.name`,
`mcp.protocol.version`, `jsonrpc.request.id`, and for `tools/call` sets
`gen_ai.operation.name = "execute_tool"` and `gen_ai.tool.name`; it parents the span with
`extract_trace_context(ctx.meta)` **[SOURCE]** (`mcp/server/_otel.py:14-45`), which extracts
W3C context and returns `None` on an absent or malformed carrier so the span falls back to
ambient parenting rather than orphaning **[SOURCE]** (`mcp/shared/_otel.py:44-57`).

So the work is: **confirm the caller's trace and the Aegis run's spans land in one tree**,
and that the tool span the SDK opens is the parent of the `gen_ai.*` spans the Aegis gateway
emits. I measured that `traceparent` reaches `ctx.meta` **[MEASURED]**; I did **not** measure
that the resulting spans share a trace id with an Aegis run, because that needs a live
collector.

**Checkable:** an in-memory span exporter test in `backend/tests/observability/` (matching
that directory's existing layout) asserting that a `tools/call` carrying a known
`traceparent` produces a span whose `trace_id` is `4bf92f3577b34da6a3ce929d0e0e4736` and
whose descendants include the tool's own spans.

### M4 — Honour `resultType` — decide, then implement one of two things

`on_call_tool`'s SDK signature already permits returning
`CallToolResult | InputRequiredResult` **[SOURCE]** (`mcp/server/lowlevel/server.py`,
`on_call_tool` overload). The interesting question is whether Aegis *should* return one.

**It has an obvious candidate and a real reason not to.** The candidate: HIGH-risk tools,
which today are listed but never executed — a call files a `PENDING` approval row and returns
the approval id **[SOURCE]** (`server.py:70-79`). MRTR is the protocol's way to say "I need
something more from you before I can finish".

**But MRTR's contract is that the client retries the original request carrying
`inputResponses`** **[DOC]** (major 7), and Aegis's approval is granted **out of band by a
different human in a different portal**, on a timescale of minutes to days. That is not an
input the calling client can supply. Modelling it as MRTR would be a lie in a standard
field.

**Recommendation: return `resultType: "complete"` for HIGH-risk calls, exactly as today,
with the approval id in the content — and write down that this is deliberate.** The SDK
stamps `"complete"` automatically **[MEASURED]**, so the *implementation* of this task is
one comment and one test.

Reserve MRTR for a case that actually fits: a tool missing a required argument that the
*calling client* can supply. There is no such tool today, so **this task is a decision, not
code**.

### M5 — Behaviour of clients that send no version header

Era routing is **header-only** in this SDK release, and the SDK says so: "TODO(L49):
header-only era-routing for now; body-primary classification is a follow-up" **[SOURCE]**
(`mcp/server/streamable_http_manager.py:174-177`). A request with **no**
`MCP-Protocol-Version` header falls to the legacy stateful path
(`server.py`'s `build_http_app` passes no `stateless_http`, so `stateless` is `False`
**[SOURCE]** `server.py:1438-1457`).

**This is the compatibility surface and it needs one test per era**, not a claim. Old
clients keep working *because* the legacy path is still there — that is a property of
`mcp 2.0.0`, and it will not survive `mcp 3.x`.

### M6 — `subscriptions/listen` — **recommend not implementing**

The SDK ships `ListenHandler` and an `InMemorySubscriptionBus` **[SOURCE]**
(`mcp/server/subscriptions.py:1-22, 94-127`), and `get_capabilities` derives every
`listChanged` flag and `resources.subscribe` from *whether that handler is registered* when
the protocol version is modern **[SOURCE]** (`mcp/server/lowlevel/server.py:584-586`).

Aegis's MCP server currently advertises `{"tools":{"listChanged":false}}` and has no change
notifications at all. Adding `subscriptions/listen` means holding a long-lived POST stream
per client, with an in-process bus that **does not fan out across replicas** — the SDK's own
docstring says each replica's bus invokes only *its local* listeners **[SOURCE]**
(`subscriptions.py:73-87`). For a single-process demo that is fine; as a claimed capability
it is a distributed-systems promise nobody has costed.

**Recommendation: skip it, and leave `listChanged` false — which is the truth.** Revisit only
if a console feature actually needs push.

### M7 — Re-examine `McpTransportMount`

`McpTransportMount` exists because "a `StreamableHTTPSessionManager`'s `run()` context is
**single-use** — the SDK says so in as many words", so the mount holds a restartable slot and
a request arriving with the slot empty gets a 503 naming the cause rather than the SDK's
`RuntimeError: Task group is not initialized` surfacing as a 500 **[SOURCE]**
(`server.py:1459-1490`).

That constraint is unchanged in `mcp 2.0.0` — `_handle_request` still raises
`RuntimeError("Task group is not initialized. Make sure to use run().")` when
`self._task_group is None` **[SOURCE]** (`streamable_http_manager.py:173-174`), and the
modern path is reached *after* that check. **So keep `McpTransportMount` exactly as it is.**
This task is "confirm and add a regression test", and the finding is that the workaround is
still load-bearing.

### M8 — Client-side version negotiation — **already correct; assert it**

The brief asks for client-side negotiation so handshake-era peers keep working. **The repo
already gets this for free and I do not think anyone realised.**

`app.mcp.client` constructs `mcp.Client(streamable_http_client(spec.url, http_client=http))`
**[SOURCE]** (`backend/src/app/mcp/client.py:751-763`), and `Client.mode` defaults to
`"auto"` **[SOURCE]** (`mcp/client/client.py:332`). In `"auto"`, the SDK probes
`server/discover` at `LATEST_MODERN_VERSION`, and falls back to `initialize()` when the peer
returns any RPC error, returns an unparseable result, or answers `discover` while advertising
no modern version — with one corrective re-probe when the peer names a mutual modern version
via `-32022` **[SOURCE]** (`mcp/client/_probe.py:55-110`).

So a handshake-era peer already works, a modern peer already works, and the negotiated value
already reaches `ProbeResult.protocol_version` **[SOURCE]** (`client.py:1069`).

**The task is therefore two tests, not a change**: one against a handshake-only fake peer
(expect a `2025-11-25`-era value), one against a modern-only fake peer (expect
`2026-07-28`). Put them in `backend/tests/mcp/test_peer_url.py`'s neighbourhood — that
directory already holds `test_client.py`, `test_hostile_peer.py`, `test_peer_url.py`
**[MEASURED]**.

**One risk worth naming:** `Client` also enables client-side response caching by default —
`cache: CacheConfig | None = field(default_factory=CacheConfig)`, which "honors server
`ttlMs`/`cacheScope` hints with a per-client in-memory store" **[SOURCE]**
(`mcp/client/client.py:360-368`). Aegis constructs a fresh `Client` per probe **[SOURCE]**
(`client.py:762`), so the blast radius today is one connection — but if peer clients are ever
pooled across tenants, a `"public"`-scoped peer response could be shared. **Assert the
per-connection lifetime, or pass `cache=None`.**

### V1 — `server/discover`

```bash
curl -s -X POST http://127.0.0.1:8000/mcp/mcp \
  -H "Authorization: Bearer $TOKEN" \
  -H 'MCP-Protocol-Version: 2026-07-28' \
  -H 'Mcp-Method: server/discover' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{"_meta":{
        "io.modelcontextprotocol/protocolVersion":"2026-07-28",
        "io.modelcontextprotocol/clientCapabilities":{}}}}'
```

Expect HTTP 200 and, by analogy with the measured synthetic run:
`result.supportedVersions == ["2026-07-28"]`, `result.resultType == "complete"`,
`result.capabilities.tools` present, `result.capabilities.resources` present (Aegis registers
`on_list_resources` and `on_read_resource` **[SOURCE]** `server.py:1380-1381`), and
`result._meta["io.modelcontextprotocol/serverInfo"] == {"name":"tcs-adapter-tools","version":"2.0.0"}`
**[SOURCE]** (`server.py:141,144`).

**`Mcp-Method` and `Mcp-Name` are now required headers on Streamable HTTP POSTs** **[DOC]**
(minor 4) — omit them and expect `HeaderMismatch` (`-32020`, renumbered from `-32001`
**[DOC]**, minor 12). That negative case is worth a test on its own.

### V2 — `tools/list` carries cache hints and is persona-filtered

Same envelope, `"method":"tools/list"`, `Mcp-Method: tools/list`. Expect:

* `result.ttlMs` == the number chosen in M2;
* `result.cacheScope == "private"` — **assert this literally**;
* `result.resultType == "complete"`;
* the tool names equal `tool_definitions_for(_persona_for(role))` for this token's role, and

Run it with **two tokens of different roles** and assert the lists differ. If they do not,
either the seed has one role or the filter is not running; find out which.

## Risks, and what would make me abandon or reduce this

1. **The authenticated modern round trip against the real app is unmeasured.** Everything
   downstream assumes `resolve_caller` (`server.py:489`) works when the transport hands it a
   modern request context. It reads identity off `ServerRequestContext.request` — "which the
   transport attaches per inbound POST" **[SOURCE]** (`server.py:31-33`) — and the modern
   path is a different code path in the SDK. *Abandon trigger:* if `ctx.request` is not
   populated on the modern path, per-call identity breaks and **the modern era must be
   refused outright** (reject the header) until it is fixed. Never fall back to
   connection-scoped identity.
2. **`mcp 2.0.0` is a major version and this revision removes things.** The legacy path is
   present today; the SDK's own routing comment is a `TODO(L49)` **[SOURCE]**
   (`streamable_http_manager.py:174`), which is the shape of code that changes. **Pin `mcp`
   and `mcp_types` exactly and vendor the wheels.**
3. **`cacheScope` is a one-word security control.** `"public"` on a persona-filtered
   `tools/list` would let an intermediary serve one caller's allowlist to another **[DOC]**.
   The default is already `"private"` **[MEASURED]**; the risk is a future edit, which is why
   V2 asserts the literal.
4. **No SSE resumability any more.** "Remove SSE stream resumability and message redelivery
   … A broken response stream loses the in-flight request; clients **MUST** re-issue it"
   **[DOC]** (major 9). A long `tools/call` behind a proxy with a short idle timeout now
   fails differently. The SDK mitigates with a keepalive ping that commits SSE when a handler
   runs silent past `_SSE_PING_INTERVAL` **[SOURCE]**
   (`mcp/server/_streamable_http_modern.py:9-17`) — **I did not measure that interval or test
   it behind a proxy.**
5. **MRTR is a tempting wrong fit for the approvals gate** (M4). Modelling an out-of-band
   human approval as an `input_required` the *client* must satisfy would be a false claim in
   a standard field.
6. **`subscriptions/listen` would advertise a distributed capability backed by an in-process
   bus** (M6). *Reduce trigger:* it already fires — do not build it.
7. **Client-side response caching is on by default in `mcp.Client`** **[SOURCE]**
   (`client.py:360-368`). Harmless while a `Client` is per-probe; a latent cross-tenant leak
   if peer clients are ever pooled.

## What this plan does NOT cover

* **The `io.modelcontextprotocol/tasks` extension.** Tasks moved out of core into an official
  extension with `tasks/get` + `tasks/update` and no `tasks/list` **[DOC]** (major 6). Aegis
  uses none of it.
* **`subscriptions/listen`** beyond the recommendation not to build it (M6).

  Client Registration, credential-to-issuer binding, and DCR's deprecation in favour of

  tokens at `POST /v1/auth/login`; there is no separate authorization server" **[SOURCE]**

  **[MEASURED]** needs to change.** That is a real gap.
