# HONESTY_AUDIT.md — Claim-vs-Reality (whole-repo)

Adversarial audit (5 parallel auditors: guardrails/security · retrieval/evals/data ·
observability · agent/ML/governance · frontend/docs). Each finding: the claim, the
reality (file:line), and the **disposition** — **MAKE-REAL** (build it) or **ALIGN-DOCS**
(the claim is wrong/aspirational; correct the wording to match the code). Ranked worst-first.

> Headline: the platform is genuinely honest at the *engine* level and the frontend has
> **no fabricated-as-live data**. The gaps are (a) two ML wiring bugs that make the ML
> story dead-at-runtime, and (b) several headline claims (full-tracing, RAGAS, NeMo,
> Garak, durable cross-worker resume, ReAct loop, graded autonomy bands) that overstate
> what the code does.

## CRITICAL
1. **ML never runs in the agent.** `agent/deps.py:_get_shared_store` calls `generate_synthetic()` WITHOUT `await` (it is `async def`) → store is empty (size 0) → no subject → `ml_predict` early-returns → `predict_explain` is never called. Tests pass only via injected fakes. → **MAKE-REAL:** await it; add an agent-path test asserting a real `ml_explanation` + non-empty store.
2. **The model is trained on generic noise, not the domain.** `ml/spec.py:resolve_spec` reads lowercase `features/target/training_frame`; the adapter exposes `FEATURES/TARGET/feature_matrix` (a module) → silent fallback to `FALLBACK_SPEC` (`feature_0..3`). The committed `ml_spine.joblib` never saw the domain; real inputs return a constant `~0.0152`. `feature_matrix`/`latent_resolution_hours` are called by nothing. → **MAKE-REAL:** wire the adapter spec (lowercase alias or read `FEATURE_NAMES`/`TARGET`/`feature_matrix`), one-hot categoricals, retrain the artifact on `feature_matrix(dataset)`; test distinct predictions for distinct inputs.
3. **OTel "full taxonomy / every action fully traced" is 2/8.** Only LLM `chat` + `embeddings` spans exist (+ a bare `agent.run`). Retrieval, rerank, guardrails, tools, and per-node work emit NO spans (they use perf-counter stream events). trace_id→audit link IS real. → **RESOLVED (real nested span tree):** a dependency-free `observability/spans.py` `span(kind, name, attributes)` helper stamps `openinference.span.kind` (from `semconv.SpanKind`). The root `agent.run` is now marked **AGENT** (`orchestrator.py`); the `_timed` node wrapper (`agent/graph.py`) opens a span per graph node so each emits BOTH its stream event AND a span — `guard_input`/`guard_output` as **GUARDRAIL** (stage+verdict+layer), `retrieve` as **RETRIEVER** (query + N candidates → K results), the rest **CHAIN**; each tool execution in the `act` node is a **TOOL** span (name+risk+ok); the rerank stage (`retrieval/pipeline.py`) is a **RERANKER** span; existing LLM/embedding `gen_ai.*` spans now also carry **LLM**/**EMBEDDING** kinds. All nest under `agent.run` so Phoenix renders one tree. Instrumentation degrades to a **no-op** when no tracer/Phoenix is configured (tests + lite mode); the trace_id→audit link is **preserved**. Biting test `tests/agent/test_span_tree.py` runs a query through the graph with fakes (offline) and asserts the AGENT root plus nested GUARDRAIL/RETRIEVER/TOOL/CHAIN spans; `test_rerank_emits_a_reranker_span` covers the RERANKER span.
4. **"RAGAS" is hand-rolled overlap proxies** — no `ragas` lib; `faithfulness`/`answer_relevancy` don't exist; the eval code's own docstring says "proxies", but `backend.md §8` names "RAGAS" flatly. The **LLM-as-judge is never called in the gate** (only a skipped test). → **MAKE-REAL** (wire the judge into `evaluate()` + thresholds) **+ ALIGN-DOCS** (say "RAGAS-style proxies + optional LLM judge"); optionally add real `ragas`.

## HIGH
5. **NeMo Colang is decorative** — `nemoguardrails` isn't installed; `build_rails()`/`LLMRails` are called nowhere; the `.co` files run at no point. → **RESOLVED (wired for real):** `nemoguardrails` installed (pins `pandas<2.4`); `nemo.get_engine()` builds `LLMRails` over the Colang config; `nemo_check_input`/`nemo_check_output` run the input/output flows (input-/output-rail-only, no `main`-model generation) and are selected by `GUARDRAILS_ENGINE=nemo` in `rails.py`. Proven by `tests/guardrails/test_nemo_rails.py` (blocks a jailbreak, redacts PII — real engine, offline). Injection also gained a deterministic signature backstop shared by both front doors (finding #13).
6. **Garak is a pure doc claim** — zero code/artifact; docs script "we ran N probes, here's the block-rate." → **DECISION:** add a `scripts/` Garak runner + commit a real block-rate report, OR remove the claim. **RESOLVED (real deferred runner):** `backend/scripts/garak_scan.py` is a real, runnable Garak red-team runner (gateway base-model + guarded `/query` targets, curated probe set) executed **on the day** (needs the gateway key + network); docs now say "run it on the day, results committed then" and it honest-degrades (exit non-zero, no report) when garak/key/network is absent — **no fabricated results**.
7. **LightRAG ingest returns hardcoded `(0,0)`** entities/relations. → **RESOLVED (real counts):** `lightrag_backend.ingest_chunks` now snapshots the graph store's node/edge totals before/after `ainsert` and reports the real delta; the lite/offline backend returns honest `None` (unknown), never a fabricated number; `IngestReport.entities/relations` are `int | None`. Tested (`test_lightrag_backend.py`) — asserts non-zero measured deltas, per-ingest (not cumulative), and honest `None` without a graph store.
8. **"Durable PostgresSaver / resume on any worker" not implemented.** → **RESOLVED (real cross-worker resume):** a process-wide shared checkpointer (`data/session.get_agent_checkpointer`) that every compiled graph binds to; `resume_parked_run` rehydrates from the checkpoint by `thread_id` when the in-process handle is gone (fresh worker), guarded by the existing `PENDING→RESUMING` optimistic lock for exactly-once across workers. Biting test replaces the registry with an empty one and proves the tool executes exactly once. (True cross-*process* run needs `langgraph-checkpoint-postgres` + a live Postgres on the day; the rehydration code path is validated against the shared saver.)

## MEDIUM
9. **"ReAct / plan-and-execute loop" is a single linear pass.** → **RESOLVED (real self-repair loop):** the graph is now `plan → gate → act → reflect → (plan | generate)` with a bounded iteration budget (`AgentConfig.max_plan_iterations`, hard cap → guaranteed termination). `reflect` judges the tool outcome; a failed/insufficient action re-plans (feeding the failure back), a success generates. New optional `reflection` stream event. Tests bite: a failing action triggers a second tool call, a success does not loop, and the budget caps the rounds.
10. **Graded conformal autonomy bands** — README/ADR-0007/UI copy claim "conformal confidence decides autonomy"; live backend runs a **binary risk gate** with ML deliberately excluded (the founder's ML-as-signal decision). Bands only appear in mock. → **ALIGN-DOCS:** update README/ADR-0007→Superseded/DualVerdict/AutonomyBand copy to "risk-gated approval; ML is a solution signal, not a gate."
11. **"Output schema validation"** is only a length + control-char check. → **RESOLVED (honestly named):** the code is `validate_output_format` and its docstrings say "structural shape / format validation," not "schema validation" — the claim now matches the implementation (length + control-char + the content filter below).
12. **Content filter** = a 3-string denylist. → **RESOLVED (broadened):** `_OUTPUT_DENYLIST` is now a curated leak-marker set across three shapes — chat-template control tokens (`<|im_start|>`, `[/INST]`, `<<SYS>>`…), explicit system-prompt framing, and verbatim echoes of this platform's own instruction preamble — chosen to avoid false positives; still an explicit backstop layered after PII redaction, not a moderation model (stated as such).
13. **Input injection has no deterministic backstop.** → **RESOLVED:** `classifier.detect_injection` runs a deterministic signature set (jailbreak/override/leak patterns) with **no API call** first, then the cheap-model classifier — used by both the programmatic `check_input` and the NeMo Colang `self_check_injection` action, so injection defense never depends solely on the API.
