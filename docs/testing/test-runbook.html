Start here: tenant isolation

This is the single most important thing to test, and the fastest way to embarrass the platform if it is wrong. Two tenants exist — Northwind (tenant 1) and Vertex (tenant 2). Use two browser profiles, or one normal and one private window, so both sessions live at once.

Spend must not leak

Sign in as northwind.client in one window and vertex.client in the other. Open Savings on both.

Correct: the two figures differ and each matches only its own tenant's spend. Right now Northwind reads about $2.69 actual / $3.14 saved and Vertex about $0.15 / $0.28. Now run a query as Northwind and refresh both — Northwind moves, Vertex must not move at all. Why this one first: until today this screen showed every tenant the same process-wide number, so one tenant's query visibly moved another tenant's money. It is fixed and ledger-backed — this is the test that proves it.

Knowledge must not leak

Open the Graph section as an AI-team or admin account on each tenant.

Correct: Northwind shows around 50 nodes / 49 edges — real entities like Baltic Freight Ltd, Anna Kowalski, Operations Committee. Vertex shows an empty graph, because nothing has been ingested for Vertex. Empty here is the right answer, not a bug.

Decisions must not cross

As northwind.admin, open Approvals and try to act on Vertex's gate.

Correct: you only see your own tenant's gate. A platform gate shows for admin only, and a tenant's own admin is the one who decides a tenant gate — the buttons are disabled with the reason stated, not silently missing.

Documents must not cross

Open Documents as each tenant.

Correct: Northwind's filenames are all northwind-* / policy files; Vertex's are vertex-*. Neither lists the other's.

Tenant admin

Runs one tenant. This is the richest portal and the one a jury will most likely explore — it has documents, prompts, memory and approvals all in one place.

Sign in northwind.admin or vertex.admin / demo 13 sections

Documents → Jobs → Graph — the full ingestion chain

This is the best single demo in the product. Upload a PDF on Documents (PDF only — other types are refused with a clear reason). Then watch Jobs. Then open the graph.

Correct: the upload returns a real workflow_id; a new job appears in Jobs and walks six stages — parse, chunk, enrich, embed, index, graph; it finishes SUCCEEDED; and new entities from your document appear in the knowledge graph. That is Temporal, Docling, Qdrant and Neo4j all doing real work.

LLM Ops — prompts fixed today

Open the prompt editor. Read what is in the box before touching anything. Then try Make live, and try saving an empty body.

Correct: the box either holds the live prompt text, or says plainly that the shipped prompt is running and its text is not on this API. Make live asks first and names the version it will displace. An empty body is refused outright, with the reason on the disabled button. Was dangerous: the editor loaded blank while a prompt was live, so one click could replace a tenant's entire operating prompt with nothing. There was no confirmation and no way back.

Approvals fixed today

Click Approve, then back out. Then commit a decision.

Correct: the first click arms and fires no request — it asks, naming every call the approval will run, not just the first one, and says it cannot be recalled. "Keep waiting" restores it untouched. Only the second click decides.

Memory fixed today

Have a two-turn console conversation, then come back here. Rename a chat. Delete a chat.

Correct: the agent recalls the earlier turn in turn two — memory is real, not decorative. Rename and Delete now actually fire requests (both were completely inert), Delete asks first, and the list re-reads from the server afterwards.

Analytics fixed today

Load the page and switch periods.

Correct: every board renders. If you see a wall of failures, tell me — that was a real defect where one expired token took all eighteen boards down at once, and it now recovers by itself.

Governance, Roles, Forecast, Audit, Console

Set a per-user cap above your tenant's cap. Export a forecast CSV.

Correct: the over-tenant cap is refused with a sentence naming the cap that actually binds — a stored number that could never apply is worse than a refusal. The CSV header states the scope it was taken under.

Cache — the two accounts differ fixed today

Look at the left rail as northwind.analyst, then as ai.

Correct: ai has a Cache item and it loads. northwind.analyst has no Cache item at all. A cache hit rate is one number across every tenant sharing the worker, so a tenant-pinned account genuinely may not read it — and the rail no longer offers a page that can only refuse. This is the exact "always refused, never loads" you hit earlier. The gate is the tenant pin, not the role name.

Console — the agent proper

Ask something that needs a tool. Then ask something that should trip the human gate, e.g. asking it to issue a credit or update a request's status.

Correct: you see the run stream live — plan, guardrail, retrieval, tool calls, reflection, synthesis — and a cost. A risky action parks the run and appears in Approvals; approving it resumes and executes exactly once; rejecting ends the run as rejected, not "completed".

Console — mode picker and fan-out

Set the mode to Team and ask a broad question.

Correct: multiple sub-agent lanes appear and run in parallel, each streaming its own reasoning, then a synthesis step merges them. The run records the width and who chose it.

Console — image attachment fixed today

Attach an image.

Correct: if it is refused, you are told which of two things happened — the screen flagged your image, or the screen could not run and it failed closed as a precaution. Those are different facts and the second one may pass on a retry. It used to say only "no description was produced".

Known & expected — not bugs

Things you will hit that are either deliberate or already on my list. Worth knowing so you do not spend time reporting them.

Awaiting your decision

As northwind.analyst, LLM Ops and parts of Guardrails refuse with a 403.

This is the open policy question I asked you about. Should a tenant's own AI team operate their own tenant's prompts, and see their own security posture? My recommendation: yes to prompts (the scoping already exists and you already allow tenant admins), no to posture and red-team (those are deployment-wide facts that cannot be narrowed to a tenant). Say which and I will implement it.

Six documents sit at PENDING forever

Documents 1–6 (northwind-*, vertex-*) never ingest.

Deliberate. The seeder creates them as records, not bytes — there is no file behind them, so it refuses to claim a parse and a chunk count that never happened. Every real upload you make will ingest properly. Tell me if you would rather they were real files so the demo has no permanently-queued rows.

The client Analytics tile refuses part of its data

A client account calling a tenant-admin usage endpoint. Same class as the Cache fix — either the panel should not be on that portal, or the endpoint should admit a client scoped to itself. On my list.

"Not recorded" is a real answer

Run latency, queue depth and several pipeline figures will say not recorded with a ⓘ explaining what would fill them. That is the platform refusing to fabricate a zero. It is a feature, and it is worth pointing at during a demo.

Budgets can stop the platform — on purpose

If queries or ingestion start failing with BudgetExceededError, a cap was hit. That happened during the audits and blocked Northwind entirely; caps are now 50M tokens / $200 per tenant per day. It is correct enforcement, not a fault — but raise the caps rather than debugging the agent.
